Every chaos action hits only the instance that served the request. Behind a load balancer, that's whichever instance the LB picked. Each result shows which instance it was.

Health check

Changes what /api/health returns. The load balancer uses it to decide whether this instance gets traffic.

5xx errors

Fires requests that return HTTP 500. Enhanced health turns Degraded or Severe as the error rate climbs.

Slow responses

nginx gives up after 60 s and returns 504. Try 65000.

CPU burn

Keeps CPU cores busy so Auto Scaling has a reason to add instances (Lab 8).

Memory leak

Holds memory until released. Keep going on a t3.micro (1 GB) and the Linux OOM killer ends the process.

Freeze the event loop

Node can't answer anything, health checks included. Watch nginx return 502 or 504.

Crash the process

Exits with code 1. Beanstalk's process manager restarts it. The PID and uptime on Overview reset.

Write a log line

Find it with eb logs or in CloudWatch Logs (Lab 4).

Database connectivity

Opens a TCP connection to RDS_HOSTNAME/RDS_PORT (an RDS database attached to the environment) or DB_HOST/DB_PORT (your own properties). A timeout almost always means a security group problem.

Simulate an SQS message

In a worker environment, the SQS daemon POSTs each message to this app. This button sends the same kind of request from your browser so you can try it locally. Include FAIL in the body to get a 500, which makes SQS retry.
